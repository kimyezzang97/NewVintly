# 사용자 차단 API

내가 차단한 회원의 글과 댓글이 **내 화면에서만** 보이지 않게 한다. 차단은 단방향이며 상대는 차단 여부를 알 수 없다.

## 인증

- 로그인한 회원만 호출 가능
- 요청 헤더에 access 토큰을 담아 전달 (`Authorization: Bearer` 형식이 **아님**, 헤더 이름 자체가 `access`)

```
access: {accessToken}
```

- 미인증 시 응답: `401`

## 오류 처리 방식 (중요)

**인증 오류(401)를 제외한 모든 오류는 HTTP 상태가 `200`으로 내려온다.** 실패 여부는 응답 본문의 `success` / `code`로 판단한다. 이 서버 전체의 응답 규약이며 신고 API와 동일하다.

---

## 차단이 적용되는 범위

| 화면 | 차단 시 |
| :--- | :--- |
| 커뮤니티 게시글 목록 | 차단한 회원의 글이 사라진다. 전체 건수(`totalElements`)도 함께 줄어든다 |
| 게시글 댓글 | 차단한 회원의 댓글이 사라진다 |
| 매장 댓글 | 차단한 회원의 댓글이 사라진다 |
| 게시글 상세 | **적용되지 않는다.** `boardId`로 직접 열면 그대로 보인다 |

차단당한 회원은 **내 게시글과 내 댓글에 댓글을 달 수 없다**(`403`). 상세는 아래 참고.

---

## 앱에서 반드시 알아야 할 두 가지

### 1. 댓글 수가 실제와 어긋난다

차단한 회원의 **최상위 댓글을 가리면 거기 달린 남의 대댓글도 함께 사라진다.** 차단과 무관한 제3자의 답글까지 없어진다.

그래서 게시글 목록의 `commentCount`(서버가 세어 준 값)와 상세 화면에서 실제로 받는 댓글 개수가 다를 수 있다.

- 목록의 `commentCount`는 **차단을 반영하지 않은 전체 개수**다.
- 상세의 댓글 배열은 **차단이 반영된 결과**다.

"댓글 5개"라고 표시했는데 열어 보니 2개인 상황이 생긴다. 상세 화면의 개수는 서버 값이 아니라 **받은 배열의 길이로 표시할 것.**

### 2. 게시글 상세는 차단이 적용되지 않는다

목록에서 가려진 글이라도 `GET /api/v1/boards/{id}`로 열면 정상적으로 내려온다. 목록에서 사라졌으니 도달할 일이 드물다고 보고 막지 않았다.

이전 화면에 남아 있던 `boardId`로 진입하는 경로가 있다면 앱에서 처리하거나 서버에 요청할 것.

## POST /api/v1/blocks

회원을 차단한다.

### Request Body

| 이름 | 타입 | 필수 | 설명 |
|---|---|---|---|
| memberId | Long | Y | 차단할 회원 ID. 1 이상 |

```
POST /api/v1/blocks
Content-Type: application/json
access: {accessToken}
```

```json
{ "memberId": 2 }
```

### Response

HTTP `200`

```json
{
  "success": true,
  "code": 200,
  "msg": "차단했습니다.",
  "data": null
}
```

**이미 차단한 상대를 다시 차단해도 성공으로 응답한다.** 차단은 설정이라 "이미 그 상태"가 오류가 아니다. 신고 API가 중복을 `409`로 막는 것과 반대이므로 주의할 것.

### 실패 응답

| code | msg | 원인 |
|---|---|---|
| 403 | 자기 자신은 차단할 수 없습니다. | 본인 ID로 요청 |
| 404 | 회원 정보를 찾을 수 없습니다. | 없는 회원 또는 이미 탈퇴한 회원 |
| 400 | 차단할 회원을 선택해주세요. | `memberId` 누락 |
| 400 | 회원 ID가 올바르지 않습니다. | `memberId`가 0 이하 |

---

## DELETE /api/v1/blocks/{memberId}

차단을 해제한다.

```
DELETE /api/v1/blocks/2
access: {accessToken}
```

### Response

HTTP `200`

```json
{
  "success": true,
  "code": 200,
  "msg": "차단을 해제했습니다.",
  "data": null
}
```

**차단하지 않은 상대를 해제해도 성공으로 응답한다.** 결과("차단하지 않은 상태")가 같기 때문이다. 해제 후에는 상대의 글·댓글이 다시 보이고, 상대도 다시 댓글을 달 수 있다.

---

## GET /api/v1/blocks

내가 차단한 회원 목록을 최신순으로 조회한다. 페이지네이션 없이 전체를 반환한다.

```
GET /api/v1/blocks
access: {accessToken}
```

### Response

HTTP `200`

```json
{
  "success": true,
  "code": 200,
  "msg": "",
  "data": [
    {
      "memberId": 2,
      "nickname": "차단한사람닉네임",
      "createdAt": "2026-09-03T12:00:00"
    }
  ]
}
```

차단한 회원이 없으면 `data`는 빈 배열(`[]`)이다.

#### data[] 필드

| 이름 | 타입 | 설명 |
|---|---|---|
| memberId | Long | 차단당한 회원 ID |
| nickname | String | 차단당한 회원의 현재 닉네임 |
| createdAt | String (ISO-8601 LocalDateTime) | 차단한 시각 |

닉네임이 함께 오므로 차단 관리 화면에서 추가 조회 없이 그릴 수 있다.

## 댓글 작성 차단 (403)

차단당한 회원이 댓글을 달려고 하면 **댓글 등록 API가 실패한다.** 차단 API가 아니라 기존 댓글 등록 API의 응답이다.

```
POST /api/v1/boards/{boardId}/comments
POST /api/v1/vintages/{vintageId}/comments
```

```json
{
  "success": false,
  "code": 403,
  "msg": "댓글을 작성할 수 없습니다.",
  "data": null
}
```

### 언제 발생하는가

| 상황 | 결과 |
| :--- | :--- |
| 나를 차단한 회원의 **게시글**에 댓글 | 403 |
| 나를 차단한 회원의 **댓글**에 대댓글 | 403 |
| 매장의 최상위 댓글 | 항상 허용 (매장에는 글쓴이가 없다) |
| 내가 차단한 회원의 글에 내가 댓글 | **허용** |

마지막 줄에 주의할 것. 차단은 단방향이라 **내가 누군가를 차단해도 내가 그 사람 글에 댓글을 다는 것은 막히지 않는다.** 막히는 것은 반대 방향뿐이다.

메시지는 "차단당했습니다"가 아니라 중립적인 문구다. 상대에게 차단 사실을 직접 알리지 않기 위해서다. 앱에서도 이 문구를 그대로 쓰는 것을 권한다.
